# Kindle Mail：把 Obsidian 笔记送到 Kindle 慢慢读

作者：James C

你可以在 Obsidian 写读书笔记、整理长文章，再把它们变成适合 Kindle 阅读的电子书。Kindle Mail 会在本机生成 EPUB，用你自己的邮箱推送到 Kindle，不需要在插件里登录 Amazon 账号。

这是独立社区项目，与 Amazon、Obsidian 无隶属或背书关系。插件免费，采用 MIT 开源许可证。

## 一、先理解两个按钮

| 命令 | 做什么 | 什么时候用 |
| --- | --- | --- |
| 发送当前笔记到 Kindle | 自动生成 EPUB，确认后通过邮件推送 | 想直接到 Kindle 上阅读 |
| 导出当前笔记为 EPUB | 把 EPUB 保存到仓库内的文件夹 | 检查排版、备份或用其他阅读器打开 |

**导出不等于发送。直接发送也不需要先导出。**

整个发送过程是：

```text
Obsidian 笔记 → 本地生成 EPUB → 发送前确认 → 你的邮箱 → Amazon → Kindle
```

它不是实时同步工具。笔记修改后需要重新发送，可能产生新文档；Kindle 上的批注不会自动传回 Obsidian。

## 二、准备条件

- 电脑端 Obsidian 1.11.4 或以上。手机端不支持。
- 一个可以正常使用的 Kindle 个人文档收件地址。
- 支持 SMTP 和应用专用密码或授权码的发件邮箱。
- 发件时能够联网；只导出 EPUB 则不需要邮箱或网络。

目前不支持必须使用 OAuth 的邮箱。Gmail、QQ、163 的具体认证条件，以各自账号和服务商设置为准。

## 三、安装

社区上架前，从 GitHub Release 下载 `main.js` 和 `manifest.json`，手动安装：

1. 在 Obsidian 打开“设置 → 第三方插件”。
2. 点击“已安装插件”右侧的文件夹图标，确保打开的是**当前仓库实际使用的插件目录**。
3. 在里面新建 `kindle-mail` 文件夹，把两个文件放进去。
4. 重启 Obsidian，回到“已安装插件”，找到 Kindle Mail 并开启。

正确结构：

```text
当前仓库/.obsidian/plugins/kindle-mail/main.js
当前仓库/.obsidian/plugins/kindle-mail/manifest.json
```

不要把 ZIP 直接放进去，也不要多套一层同名文件夹。尤其注意：如果仓库文件夹里面还有另一个仓库，应使用当前打开的那一个。

尚未上架的插件不会出现在在线插件市场的 Browse 搜索中。手动安装后，要在“已安装插件”里找。

## 四、配置 Gmail 发件

打开“设置 → Kindle Mail”，按下面填写：

| 字段 | 示例或说明 |
| --- | --- |
| SMTP 主机 | `smtp.gmail.com` |
| SMTP 用户名 | 你的完整 Gmail 地址，如 `your-name@gmail.com` |
| 发件邮箱 | 先填同一个 Gmail 地址 |
| Kindle 收件邮箱 | 你平时推送使用的个人文档邮箱 |
| SMTP 端口 | `465 · TLS`，或 Google 支持的 `587 · STARTTLS` |
| 电子书作者 | 你希望显示的作者名 |
| EPUB 导出目录 | 默认 `Kindle Exports` 即可 |

### 生成应用专用密码

Gmail 通常不能用普通登录密码进行此类 SMTP 登录。请按 [Google 官方说明](https://support.google.com/mail/answer/185833?hl=zh-Hans)：

1. 在 Google 账号中开启两步验证。
2. 打开 [应用专用密码页面](https://myaccount.google.com/apppasswords)。
3. 创建一个名为 `Obsidian Kindle` 的应用专用密码。
4. 复制生成的 16 位密码；粘贴时去掉用于显示的空格。

部分组织账号或受限账号可能没有这个选项。

### 在插件中关联授权码

1. 点击“SMTP 授权码”旁的 **Link…**。
2. 新建秘密：
   - **ID** 填 `kindle-gmail`。这只是名称，用小写字母、数字和短横线。
   - **Secret** 填 Google 生成的应用专用密码。
3. 点击 **Save**。如果返回后仍显示 Link…，再点一次，选择刚建的 `kindle-gmail`。
4. 点击“测试连接”。

占位提示 `sk-...` 不是要填写的前缀。这里不是 OpenAI API Key，也不是 Kindle 邮箱密码。

测试连接只检查 SMTP 连接与认证，不会发送邮件，也不能验证 Amazon 是否能收到。

## 五、在 Amazon 允许发件人

在 Amazon 的“管理内容与设备 → 偏好设置 → 个人文档设置”中：

1. 找到你的 Kindle 个人文档邮箱，填入插件的“Kindle 收件邮箱”。
2. 将实际发件的 Gmail 地址加入“认可的个人文档电子邮件列表”。

如果以前只允许 Hotmail 发件，改用 Gmail 后，需要另外加入 Gmail。不要把 Gmail 的 SMTP 登录和 Hotmail 的发件地址混用，除非你已经配置了受支持的发件别名。

入口和名称可能随 Amazon 站点变化，参见 [Amazon 官方邮件推送说明](https://www.amazon.com/gp/sendtokindle/email)。

## 六、发送第一篇文章

建议先用一篇短笔记测试：

1. 打开笔记，等待 Obsidian 保存当前编辑。
2. 按 **Ctrl+P**；macOS 按 **Cmd+P**。
3. 搜索“发送当前笔记到 Kindle”。
4. 检查确认窗口中的标题、收件人、附件大小、图片数量与转换提示。
5. 点击“发送”。
6. 收到“邮件服务器已接收”提示后，让 Kindle 联网并等待处理。

也可以右键一个 Markdown 文件，选择“发送到 Kindle”。常用时，在“设置 → 快捷键”中给命令设置快捷键。

**邮件服务器已接收，不代表 Kindle 已入库。** Amazon 可能还在处理，或要求验证邮件。如果发送时超时，先查看邮箱和 Kindle，避免重复推送。

## 七、导出电子书

如果想先检查排版，运行“导出当前笔记为 EPUB”。生成文件保存在当前仓库的 `Kindle Exports` 文件夹中。已有同名文件不会覆盖。

可以用 EPUB 阅读器检查。检查后想直接投递，回到原笔记运行“发送”命令即可；它会重新生成 EPUB。

## 八、图片、嵌入和不支持的内容

- 支持标准 Markdown、中文、标题、列表、引用、表格、链接与代码。
- 开头的 YAML 属性区会去掉。
- 整篇 `![[其他笔记]]` 正文默认不包含，避免意外外发其他笔记；如需要，请开启“包含嵌入笔记正文”，并在发送前核对全部笔记及图片清单。最多根笔记加两层嵌入。循环、深层嵌入、章节和块定位会显示未展开提示。
- 支持仓库内 PNG、JPEG、GIF 图片，不下载网络图片。
- 图片原始元数据不会清除。发送前确认内容适合交给邮件服务商和 Amazon。
- 不转换 SVG、WebP、PDF、Canvas、Mermaid、Dataview 等动态内容。高亮和待办框暂时没有专门转换；Callout 按普通引用处理。
- 单张图片不超过 10 MiB，图片总量不超过 20 MiB，最多 100 张；发送的 EPUB 不超过 25 MiB。邮箱可能有更低的限制。
- 笔记展开累计最多读取 100 篇、5 MiB Markdown，防止大量嵌入导致卡顿。

## 九、常见问题

**插件列表没有出现？**

检查当前仓库的位置，使用已安装插件旁的文件夹图标打开目录。确认 `main.js` 和 `manifest.json` 位于 `kindle-mail` 目录的第一层，然后刷新或重启。

**连接或认证失败？**

检查 SMTP 主机、用户名、端口，以及秘密是否已关联。Gmail 使用应用专用密码；QQ、163 通常使用其 SMTP 授权码。不要把授权码发给别人。

**连接成功但 Kindle 没收到？**

连接测试不会发件。请运行发送命令，并检查 Amazon 认可的发件人列表、收件地址、验证邮件、垃圾邮件与 Kindle 网络状态。

**哪里保存密码？**

插件通过 Obsidian 的 SecretStorage 读取密码，普通设置文件只保存秘密名称。秘密存储由 Obsidian 管理，不能把它当成对其他已安装插件的隔离保护。

**是否经过开发者的服务器？**

没有。电子书本地生成，确认后通过你的邮箱交给 Amazon。测试连接也会向你配置的 SMTP 服务认证。导出文件可能随你的仓库同步设置上传。

## 十、实测记录

2026-10-20，作者在 Windows、Obsidian 1.14.4 环境使用 Gmail（465 TLS）确认 0.1.2 成功送达 Kindle，正文及本地图片显示正常。其他系统和邮箱尚未完成实测。邮件服务器接收不代表 Kindle 已经处理完成；不要因短暂延迟连续重发。
