# Kindle Mail 社区发布步骤

作者：James C。GitHub 账号：Cloud2025-art。

此文件描述待执行的发布流程，不能视作已经创建仓库、发布 Release 或通过社区审核。建议仓库名：`kindle-mail`。如果名称已被你使用，应核对现有仓库内容，避免覆盖其他项目。

## 已准备的材料

- `src/`：可阅读的插件源码。
- `manifest.json`：插件 ID `kindle-mail`，版本 `0.1.2`，作者 James C。
- `README.md`：英文介绍、安装、邮箱设置、用法、限制和隐私说明。
- `docs/使用教程.md`：中文完整教程。
- `PRIVACY.md`、MIT `LICENSE` 和依赖许可声明。
- `package.json`、`pnpm-lock.yaml`：构建配置和锁定的依赖。
- `tests/`：不使用真实凭据、不发送真实邮件的自动检查。
- `docs/社区介绍.md`：可用于社区介绍的文案。

## 1. 发布前检查

1. 使用 0.1.2 版本做一次真实导出与 Kindle 推送测试。保持现有 `data.json`；更换同 ID 插件的程序文件即可。不要把个人设置文件上传 GitHub。
2. 核对作者、项目名、MIT 许可证和公开说明。
3. 确认本项目不包含截图中的个人邮箱、授权码、笔记或 SecretStorage 数据。教程仅使用示例邮箱。
4. 如安装目录位于 OneDrive，应确保发布的文件是本地完整副本。

0.1.2 已由作者在 Windows、Obsidian 1.14.4 中通过 Gmail 465 TLS 实测送达 Kindle，正文和本地图片均正常；其他平台和邮箱仍待验证。

## 2. 创建公开 GitHub 仓库

登录 `Cloud2025-art`，创建名为 `kindle-mail` 的公开仓库，然后上传本目录的源码和文档。仓库公开是 Obsidian 社区评审读取源码的前提。

不要上传：`node_modules`、个人 `data.json`、`.obsidian`、授权码、真实笔记、未经脱敏的截图。`.gitignore` 已列出常见排除项。

项目根目录应直接包含 README、LICENSE、manifest，而不是再嵌套一层发布文件夹。

## 3. 建立 GitHub Release

本地执行：

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
```

创建 Release：

- Tag：`0.1.2`，必须与 manifest 的版本完全一致，不能加 `v`。
- 名称：`Kindle Mail 0.1.2`。
- 说明：参考 CHANGELOG，并准确标明实测平台和已知限制。
- 单独附加 `main.js`、`manifest.json`、`LICENSE`、`THIRD-PARTY-NOTICES.md`。

仅上传 ZIP 或自动生成的 Source code 压缩包，不能满足 Obsidian 的插件安装机制。`styles.css` 不需要，因为本插件没有单独样式表。

## 4. 提交到 Obsidian 社区

按 [官方提交说明](https://docs.obsidian.md/Plugins/Releasing/Submit%20your%20plugin)：

1. 登录 [Obsidian Community](https://community.obsidian.md)。
2. 在社区个人资料中关联 GitHub 账号。
3. 进入个人后台的 Plugins，选择 New plugin。
4. 填写已经实际创建的 GitHub 仓库 URL，并选择所有者。
5. 阅读开发者政策与维护承诺，认可后提交。
6. 检查自动审核反馈；有错误时修正代码、提高版本号并发布匹配的新 Release。
7. 根据网站显示的流程完成 Publish。提交或点击 Publish 不代表已通过全部检查，也不能保证立刻出现在应用内目录中。

当前流程是社区网站提交，不应照搬旧教程向 `obsidian-releases` 添加注册表 PR。

## 5. 上架后

- 在插件目录确认能找到并安装后，再将 README 的“尚未上架”文字改成正式社区安装方法。
- 通过自己的 GitHub 仓库接收问题报告并维护版本。
- 用户已经成功接收个人版本，不等于整个社区环境或所有邮箱都完成兼容验证。
- 可以在论坛 Share & showcase 发布介绍；文案已准备在同目录，但尚未替你向论坛发帖。
